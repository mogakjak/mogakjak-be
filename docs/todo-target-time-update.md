# 할 일 목표시간 변경 (#99)

## 변경 및 재조회

`PATCH /api/todos/{todoId}/target-time`은 로그인한 사용자의 삭제되지 않은 할 일에서 목표시간만 변경한다. 제목·카테고리·날짜·완료 상태·누적 작업시간은 보존한다.

```json
{ "targetTimeInSeconds": 3600 }
```

변경도 같은 형식으로 요청한다. 설정 가능한 값은 60~86400초이며, 해제는 다음과 같다.

```json
{ "targetTimeInSeconds": null }
```

- `{}`처럼 필드를 생략하거나, 0·범위 밖 값·잘못된 JSON을 전달하면 400을 반환한다. 실패한 요청은 목표시간을 변경하지 않는다.
- 성공하면 기존 `TodoResponse` 형식으로 200을 반환한다. 변경한 목표시간 및 재계산한 달성률을 포함한다. 해제하면 두 값 모두 null이다.
- 목표시간은 같은 todoId에 저장된다. `GET /api/todos/my` 또는 기존 날짜별 목록 조회로 재조회하면 최신 값을 반환한다. 제목이 같아도 다른 todoId와 공유하지 않는다.
- 이 PATCH는 기존 전체 수정 PUT과 다르다. PUT에서 필드 생략은 #98 계약대로 목표 해제이며, PATCH에서 필드 생략은 요청 오류다.
- 타인의 할 일·삭제된 할 일에는 기존 소유권 필터를 적용하며 403을 반환한다.

## 실행 중 달성률

- 연결된 개인 또는 그룹 내 개인 세션이 RUNNING/PAUSED이면, 목표시간 변경과 같은 트랜잭션에서 세션 달성률을 즉시 재계산한다. 기존 전체 수정 PUT도 같은 경로를 사용한다.
- 계산 기준은 Todo에 저장된 누적 집중시간이다. 현재 진행 구간은 기존처럼 일시정지·종료 시 누적되며, 목표시간 변경 자체는 작업시간을 누적하거나 초기화하지 않는다.
- 다른 할 일의 활성 세션과 FINISHED 세션의 과거 달성률은 변경하지 않는다.
- 세션 전체를 다시 저장하지 않고 달성률 필드만 갱신하며, DB 쓰기 시점에도 소유자·할 일·활성 상태 조건을 확인한다. 조회 후 종료된 세션의 상태·누적시간을 덮어쓰지 않는다.
- 카운트다운 실행시간, 뽀모도로 집중·휴식·반복 설정, 세션 상태 및 완료 알림 예정은 바꾸지 않는다.
- 프론트는 PATCH 응답으로 선택한 할 일의 목표시간·달성률을 즉시 갱신한다. 이후 재개·일시정지·종료·뽀모도로 전환 응답에도 갱신한 달성률이 반영된다.
- 기존 그룹/공식 라운지 실시간 상태 응답은 제목·누적시간을 전달하며 목표시간 필드가 없으므로 새 목표시간 이벤트는 추가하지 않는다. 목표시간 전용 실시간 구독 계약은 이번 범위가 아니다.

## DB 및 검증

새 DB 컬럼 변경은 없다. #98의 nullable SQL이 기존 DB에 적용돼 있어야 목표 해제를 저장할 수 있다.

```bash
./gradlew test --tests 'com.mogakjak.mogakjak.domain.*' --tests 'com.mogakjak.mogakjak.global.*' bootJar
```

입력 생략/null 구분·범위 검증·HTTP 오류 계약·설정/변경/해제 후 재조회·다른 속성 보존·연결된 세션 동기화를 검증한다. 실제 S3 설정을 바꾸는 기존 `MogakjakApplicationTests.setCors()`는 실행 대상에서 제외한다. MySQL 마이그레이션 검증은 #98 문서의 별도 환경변수로 실행한다.

실제 JPA 갱신 쿼리 검증은 폐기 가능한 로컬 `issue99_verify` DB를 사용한다. `create-drop`으로 테스트 테이블을 생성·삭제하므로 기존 애플리케이션 DB를 연결하지 않는다. root / 빈 비밀번호의 임시 DB 기준이며, 환경변수가 없으면 해당 테스트는 건너뛴다.

```bash
ISSUE99_MYSQL_URL='jdbc:mysql://127.0.0.1:53399/issue99_verify?useSSL=false&allowPublicKeyRetrieval=true' \
  ./gradlew test --tests '*FocusSessionTargetTimeRepositoryTest'
```
